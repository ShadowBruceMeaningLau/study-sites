# 哲学站内容契约（PHILO-CONTENT-SPEC）

本文件是 `data/*.js` 课程文件的**唯一格式与质量约定**。任何新增/修改课程都必须让
`node tools/validate-curriculum.mjs` 全绿，并通过 `node tools/audit-zero-basis.mjs`。

面向的读者：想系统补上**哲学本科核心训练**的自学者（含零基础）。默认读者聪明、
但**没有受过哲学训练**——所以本契约的第一原则与 `ZERO-BASIS-STANDARD.md` 一致：
**术语首次出现就地解释，抽象结论必须配具体例子。**

---

## 0. 三条哲学站特有原则（比格式更重要）

1. **讲论证，不讲名词**。每个哲学概念必须回答三件事：
   「它要解决什么问题」→「主张是什么」→「最强的反驳是什么」。
   只介绍术语、不交代它在争论中站哪一边的内容，一律算不合格。
2. **钢人原则（principle of charity）**。介绍任何立场，必须按**最强的版本**呈现，
   再给标准反驳；禁止稻草人（straw man）。写「某某主义者认为……」时必须能指出
   这个主张的代表人物与出处，或明确说明这是教科书的标准重构。
3. **区分文本与重构**。凡引用原著，必须标明作者、著作、章节（如「柏拉图《理想国》514a」）。
   凡属教科书式重构，要写「标准重构」「学界通行读法」之类字样，不要让读者以为
   那是原文。**不得编造引文**：只能使用真正流传的原文段落或明确标注为「意译/概述」。

## 1. 文件格式（硬性）

每个课程一个文件：`data/<slug>.js`，**无 BOM 的 UTF-8**，内容**只有一条**
`window.COURSE_PACKS.push({...});` 对象字面量。

- 不允许 `import` / `export` / `require`
- 不允许函数、不允许模板字符串（**不要用反引号**，会写坏内容里的引号）
- 字符串里需要引号时统一用中文引号「」或单引号 `'`，避免转义

```js
window.COURSE_PACKS.push({
  id: "philo-intro",              // 与文件名一致，kebab-case，必须以 philo- 开头
  title: "哲学导论：哲学是什么",
  icon: "🧭",                      // 1 个 emoji
  term: "入门",                    // 见 §3 学期标签
  need: "学这门课之前需要会什么 / 零基础应该从哪讲开始。",   // 必填
  blurb: "一句话说明这门课解决什么问题，为什么值得学。",
  tags: ["入门必读", "论文写作"],
  lessons: [ /* 见 §4 */ ]
});
```

## 2. 可用 Markdown 语法（渲染器支持范围，多写的不会被渲染）

| 想要的效果 | 写法 | 说明 |
|---|---|---|
| 粗体 | `**重点**` | 支持 |
| 斜体 | `*强调*` | 支持，需在空白或括号后 |
| 行内代码 | Markdown 反引号 | **数据文件中禁止使用**（见下方警告），渲染器虽然支持，但契约层面一律改用「」标注 |
| 无序 / 有序列表 | `- 项` / `1. 项` | 支持，行首写 |
| 提示框 | `> 提示文字` | 支持，渲染成 callout |
| 表格 | `\| 列 \| 列 \|` + 分隔行 | 支持 |
| 标题 | `## 小标题` | 支持（`#` 会渲染成 h2，别用在块内） |
| **LaTeX / 数学公式** | ❌ **不支持** | 一律写成行内代码的纯文本 |

> **⚠ 关于反引号的重要澄清（规格自身的一处矛盾，以此处为准）**
>
> 契约禁止在**数据文件里**写反引号，原因是数据文件用双引号字符串承载长文本，
> 反引号很容易与内容里的引号互相破坏（历史踩坑）。但这**不是**说不要标注公式。
>
> 正确做法：**逻辑符号与公式直接写 Unicode 字符，用中文引号「」把它框起来**，
> 例如「P → Q」「∀x(Fx → Gx)」「□P」。渲染器会原样输出，读者看到的就是等宽可读的符号串。
> 校验器会检查数据文件中是否出现反引号，出现即报错。

**核心约束**：本渲染器**不认识 LaTeX**。禁止出现 `$...$`、`\forall`、`\neg` 这类写法。
逻辑符号直接写 Unicode 字符：

- 否定 ¬P、合取 P ∧ Q、析取 P ∨ Q、蕴含 P → Q、双条件 P ↔ Q
- 全称 ∀x Fx、存在 ∃x Fx、必然 □P、可能 ◇P
- 推出 ⊢ / 语义蕴含 ⊨、因此 ∴

凡符号**首次出现**必须给读法，例如：`□P`（读作「必然 P」）。

## 3. 学期 / 顺序标签

`term` 只允许下列取值（app.js 按此顺序排列课程）：

`入门` · `逻辑工具` · `第一学期` · `第二学期` · `第三学期` · `第四学期` · `专题选修`

推荐分配：导论 `入门`；逻辑、哲学史（古希腊/近代）`逻辑工具`/`第一学期`；
认识论、形而上学 `第二学期`；伦理学、政治哲学 `第三学期`；
美学、当代哲学（心灵/语言）、中国哲学 `第四学期`/`专题选修`。

## 4. Lesson（课）

```js
{
  id: "philo-intro-1",            // 全局唯一：<course 短前缀>-<短名>
  title: "哲学是什么：从「爱智慧」到可检验的问题",
  goal: "学完后你能……（一句话，可检验）",
  blocks: [ /* 讲解块，6~10 块 */ ],
  quiz: [ /* 测验题 3~6 题，见 §6 */ ],
  flashcards: [ /* 闪卡 6~12 张，见 §7 */ ],
  arguments: [ /* 论证重构 1~3 组，见 §8 */ ],
  writing: [ /* 写作训练 1~2 个，见 §9 */ ]
}
```

> **本课程不设时间线**：lesson 级**不要写 `est`（预计分钟数）**，课程级**不要写 `hours`（建议学时）**。
> 校验器会把这二者判为错误。理由只有一个：本课程只对质量有要求，
> 不告诉读者「这一讲该花多久」「这门课几个学时」——那是时间表，不是学问。
> 难度由阅读轨迹里的 `level`（深度与所需准备）标记，不用时间标记。

`flashcards` / `arguments` / `writing` 在 lesson 级，**不是 block 类型**。
一门课内建议每讲都有 `flashcards`；`arguments` 与 `writing` 可隔讲安排。

**关于 `arguments` 的 valid/sound 四种组合**（校验器会检查，这里写明以免误改）：

- `valid:true, sound:true`（有效且前提为真，如某些循环论证的结构分析）、
  `valid:true, sound:false`（形式有效但前提可疑，最常见）、
  `valid:false, sound:false`（形式无效）。
- **唯一的非法组合是 `valid:false, sound:true`**（无效论证不可能可靠）。

### blocks 可用类型

| type | 必填字段 | 说明 |
|---|---|---|
| `concept` | `title`, `md` | 核心讲解 |
| `analogy` | `title`, `md` | 生活类比，建立直觉 |
| `steps` | `title`, `items[]` | 有序步骤；item 为字符串或 `{t:"步骤", d:"解释"}` |
| `pitfall` | `title`, `items[]` | 常见误区，每条一个字符串 |
| `close` | `title`, `author`, `work`, `passage` | **原著精读**，见 §5 |
| `socratic` | `title`, `opening`, `turns[]` | **苏格拉底式提问**，见 §10 |
| `writing` | `title`, `prompt`, `considerations[]`, `rubric[]` | **写作训练**（块级版） |
| `calc` | `title`, `inputs[{name,value}]`, `outputs[]`, `note?` | 推演演练：`inputs` 给已知条件，`outputs` 给参考答案（可隐藏）。`value`/`outputs` 必须是字符串 |
| `interactive` | `lab`, `title`, `config{...}` | 交互实验，见 §11 |
| `lab` | `title`, `steps[]`, `note?` | 无交互的动手作业说明 |

**每讲至少 1 个交互式成分**：`interactive` 块，或 `socratic` 块（苏格拉底块自带交互）。
建议配比：1 个 `analogy` 开头 + 2~4 个 `concept` + 1 个 `close` + 1 个 `socratic`
+ 1 个 `pitfall` + 1 个 `calc`/`interactive`。

## 5. `close` 块：原著精读（硬性格式）

```js
{
  type: "close",
  title: "精读：洞穴与太阳",
  author: "柏拉图",
  work: "《理想国》第七卷 514a–517a",
  passage: "（原文段落。多段用 \n\n 分隔。中文可用通行中译，但必须忠实；\"+\n            \"不确定原文时改为概述并在 note 里说明。）",
  note: "选段背景与读法提示（可选）",
  annotations: [
    { line: "被引原文中的一小段话，必须与 passage 中的文字逐字一致", note: "这句话在论证里干什么、术语指什么、常见误读" }
  ],
  questions: [
    "不带提示的追问，逼读者回到文本（2~4 个）"
  ]
}
```

硬性要求：
- `annotations` 至少 4 条，`line` 必须是 `passage` 里的**连续子串**（校验器会逐条查）。
- 引用**必须标注出处**（`work` 含章节号，如 514a、§2、第二卷第九章）。
- 古典文本建议**中译 + 关键术语附希腊/拉丁/德语原词**，例如「真理（aletheia）」。
- **不得编造原文**。记不准原文时，写成忠实概述，并在 `note` 明确写「此处为内容概述，
  非逐字引文」。

## 6. Quiz（测验题）

```js
{ id:"philo-intro-1-q1", type:"single",
  q:"问题", options:["A","B","C","D"], answer:1, why:"为什么 B 对；其余选项错在哪" }

{ id:"...-q2", type:"multi", q:"...", options:[...], answer:[0,2], why:"..." }
{ id:"...-q3", type:"fill",  q:"...", answer:["可接受答案","别名"], why:"..." }
{ id:"...-q4", type:"order", q:"...", items:["打乱的选项"], answer:[2,0,1], why:"..." }
```

硬性要求：
- `why` 必填，且必须写清「为什么对 **+** 每个干扰项错在哪」，不能只写「因为 X 对」。
- `single` 的 `answer` 是整数索引；`multi` 是升序数组；`order` 的 `answer` 是正确顺序的索引数组。
- 每题 `id` 全局唯一，一门课内题干不得重复。
- 每讲至少覆盖三类：① 概念辨析 ② 论证评估/推演 ③ 易错点或立场混淆。

## 7. `flashcards`（间隔重复卡片）

```js
{
  id: "philo-intro-1-f1",       // 全局唯一
  kind: "term",                  // term 术语 | argument 论证 | figure 人物 | position 立场
  front: "正面：术语/问题/人物（首次出现给英文或原文）",
  back: "背面：大白话解释 + 一个具体例子或出处",
  hint: "可选提示",
  where: "philo-intro-1"         // 可选：相关讲 id
}
```

要求：正面**不要**是一句能靠上下文猜到的废话；背面必须包含「一句话定义 + 一个例子/出处」。
一门课里，`kind` 应覆盖术语、人物、论证、立场四类（不必每讲都全）。

## 8. `arguments`（论证重构 / 逻辑形式化）

```js
{
  id: "philo-intro-1-a1",
  title: "重构：阿奎那的「第一推动者」论证",
  source: "托马斯·阿奎那《神学大全》第一集 第 2 题 第 3 条（意译）",
  lines: [
    { t: "世上有些事物在运动。", role: "premise" },
    { t: "凡运动之物必被某物推动。", role: "premise" },
    { t: "所以必有一个不被推动的推动者。", role: "conclusion" },
    { t: "亚里士多德把物理学当第一哲学。", role: "noise" }
  ],
  hidden: true,                  // true = 隐藏句子标签，让学生自己标注（推荐）
  form: "P1: Fx；P2: ∀x(Fx → Gx)；C: ∃x(Gx ∧ ¬Hx)",   // 形式化，符号用 §2 规则
  scheme: "肯定前件 / 否定后件 / 假言三段论 / 二难 / 类比 / 归谬（选一或写「非形式」）",
  valid: true,                   // 形式是否有效
  sound: false,                  // 前提是否都为真（valid=false 时写 false）
  gap: "从有效到可接受之间还差什么：哪条前提最可疑，为什么",   // 必填，这是本练习的核心
  hint: "可选提示（先让学生自己想）"
}
```

硬性要求：
- `lines` 3~7 条，其中恰好 1 条 `conclusion`、至少 2 条 `premise`、至少 1 条 `noise`。
- `role` 只能是 `premise` / `conclusion` / `noise`。
- `gap` 必填且要有实质内容：指出**最弱的那条前提**并说明什么会推翻它。
- 若 `valid:true` 但 `sound:false`，必须在 `gap` 里说清哪条前提不成立。

## 9. `writing`（写作训练）

```js
{
  id: "philo-intro-1-w1",
  title: "小论文：哲学问题与科学问题的界线",
  prompt: "题目 + 字数（600~900 字）+ 必须回应哪些反驳",
  considerations: [ "写作前必须想清的问题 3~5 条" ],
  outline: [ { s: "引言：界定问题", d: "该写什么、不该写什么" } ],
  rubric: [ { k: "论题明确", w: "30%", d: "评分标准的具体描述" } ],
  sample: "可选：一段范例开头（3~6 句），展示什么叫「有论题的句子」",
  pitfalls: [ "常见失分点 2~4 条" ]
}
```

要求：`rubric` 至少 4 项且权重合计 100%；`considerations` 至少 3 条；
`pitfalls` 至少 2 条。`sample` 必须**明确标为范例**，不要让学生误当标准答案。

## 10. `socratic` 块：苏格拉底式提问（硬性格式）

这是本站的核心训练：**程序扮演苏格拉底，逼学生自己论证**。结构是一棵决策树。

```js
{
  type: "socratic",
  title: "追问：你说谎永远不对吗？",
  opening: "开场：情境 + 要学生面对的初始主张（一句话，别太长）",
  turns: [
    {
      id: "t1",
      prompt: "苏格拉底的追问（一个问题，不要一次问两件事）",
      note: "可选：这一问在练什么（如「区分义务论与后果论」）",
      options: [
        { t: "学生的回答（一个常见但有问题/或有道理的回答）",
          verdict: "good",              // good 站得住 | weak 有漏洞 | bad 明显错误
          reply: "苏格拉底的回应：这个回答为什么站得住/哪里漏了",   // 必填
          next: "t2"                    // 可选：跳到哪个 turn；省略 = 结束
        }
      ]
    }
  ]
}
```

硬性要求：
- `turns` 3~6 个；每个 turn 的 `options` 3~4 个。
- 每个 `option` 必须有 `verdict` 与 `reply`；`reply` 要**讲清理由**，不能只判「对/错」。
- 所有 `next` 必须指向存在的 turn id，**不得形成环**（校验器会查）。
- 至少有一条路径能让读者**找到出路**（即某个 option 的 verdict 为 `good`）——
  苏格拉底式提问的目的是逼出清晰，不是把人堵死。
- 最后至少一个 turn 不设 `next`（表示对话收敛），并在其 `reply` 里给出阶段性结论。
- 禁止「诱导式陷阱」：不要让唯一"正确"选项是显然荒谬的；干扰项要是**真有人会这么说**的。

## 11. `interactive` 实验类型

`lab` 取值与 `config` 结构（严格遵守，否则校验失败）：

- `"steplab"` —— 通用单步推演器（**哲学站主力**）：逐步展示「局面快照 + 说明」
  `config = { state:{ "立场":"…", "第几步":1 }, steps:[ {desc:"第 1 步：…", state:{...}, note:"解释"} ], legend:"说明" }`
  `state` 的值必须是字符串或数字；`steps` 至少 4 步。
  用途示例：逻辑证明的逐步推演、思想实验的条件变化、伦理困境中各要素的权衡、
  哲学史论战的回合推进。
- `"datalab"` —— 与 `steplab` 同构（保留兼容，新内容请用 `steplab`）。
- `"arglab"` —— 论证重构练习（**通常不用手写**：用 lesson 级 `arguments` 字段即可）。
- `"tablelab"` —— 真值表 / 二维判定表求值
  `config = { vars:["P","Q"], rows:[ {vals:["T","T"], cells:{"P∧Q":"T"}, note:"…"} ], cols:["P∧Q"], legend:"…" }`
  用途：命题逻辑真值表、道义矩阵、四因说/四圣谛式的分类对照。

新增 lab 类型必须先写进本文件 §11 并在 `app/philo-labs.js` 实现，否则校验器会报未知类型。

## 12. 内容质量要求（会被人工抽查）

1. **术语中英/原文并列**（首次出现）：「德性（arete / virtue）」「意向性（intentionality）」。
2. **零基础标准**（见 `ZERO-BASIS-STANDARD.md`）：术语首现就地解释；禁用的词：
   **显然、易得、众所周知、不言而喻、读者自证、显而易见、毋庸置疑**。
3. **抽象结论配具体例子**：至少一个能"亲手验一遍"的例子（情境、反例、思想实验的具体设定）。
4. **每讲有可操作练习**：`arguments` 或 `writing` 或 `interactive.tasks` 至少有一个。
5. **数字与逻辑必须自洽**：真值表、推理规则的推演结果要能被读者逐行验证。
6. **不要只讲考点**：重点是「这个立场面对什么反驳、反驳是否成立」。
7. 语言：简体中文；人名用通行中译并首次附原文（如「康德（Immanuel Kant）」）。
